## The Hook

Twenty monitoring agents across three regions need to push disk readings to your central ops store and ask which hosts are in trouble, without ever opening `ops.db` themselves. You need an HTTP service that speaks JSON, validates payloads before they reach the database, returns the right status code, and documents itself. That service is **FastAPI**, and it is a real library: `from fastapi import FastAPI` is the code that runs the route, not a comment describing one.

## Waypoint 1: Routes, Verbs, and Path Parameters

A REST API maps **HTTP verbs** and **URL paths** to Python functions. `GET` reads without changing state, `POST` creates, `DELETE` removes. FastAPI turns the decorator `@app.get("/hosts/{hostname}")` into a route and turns the function's type hints into validation.

A path segment in braces is passed to the function as an argument. Return a dictionary and FastAPI serialises it to JSON with `200 OK`. Return a typed Pydantic model and it validates the response shape too.

```python
from fastapi import FastAPI, HTTPException

app = FastAPI(title="Ops Fleet API")

FLEET = {
    "srv-01": {"hostname": "srv-01", "region": "eu", "percent": 87.0},
    "srv-02": {"hostname": "srv-02", "region": "us", "percent": 104.5},
}

@app.get("/hosts/{hostname}")
async def get_host(hostname: str) -> dict:
    key = hostname.strip().lower()
    if key not in FLEET:
        raise HTTPException(status_code=404, detail="Host not found")
    return FLEET[key]
```

Point `uvicorn app:app --reload` at that file and open `/docs`: the OpenAPI page is generated from the route and its type hints, so the documentation cannot drift from the code.

Tests do not need a port. `TestClient` wraps the `app` object and sends requests in memory, which is the fastest way to assert a `404` instead of eyeballing one:

```python nonRunnable=true reason="TestClient starts a worker thread; the browser sandbox is single-threaded. Run this locally with pytest."
from fastapi.testclient import TestClient

client = TestClient(app)

def test_missing_host_is_404():
    assert client.get("/hosts/srv-99").status_code == 404
```

### Watch out: The Trap

- Using `GET` for an endpoint that mutates data. Pre-fetchers, health checks, and retries replay `GET` freely.
- Accepting a raw `dict` as a `POST` body instead of a typed model. You lose validation, coercion, and `/docs` in one stroke.
- Declaring a filter without a default and then wondering why a bare `/hosts` fails with `422`.

## Waypoint 2: Query Parameters and Validated Request Bodies

Parameters in the signature that are not in the path become **query parameters** (`?region=eu&min_percent=90`). Defaults make them optional. FastAPI coerces them to the annotated type and rejects a non-numeric `min_percent` with `422` before your function runs.

For `POST`, declare a Pydantic model as the parameter type. FastAPI parses the JSON body, coerces fields, and returns `422` with a list of the exact fields that failed. That is Week 14's validation contract, enforced at the boundary.

```python
from fastapi import FastAPI
from pydantic import BaseModel, Field

app = FastAPI()

class ReadingIn(BaseModel):
    hostname: str
    used_gb: float = Field(ge=0)
    limit_gb: float = Field(gt=0)

HOSTS = [
    {"hostname": "srv-01", "region": "eu", "percent": 87.0},
    {"hostname": "srv-02", "region": "eu", "percent": 102.0},
    {"hostname": "srv-03", "region": "us", "percent": 95.0},
]

@app.get("/hosts")
async def list_hosts(region: str | None = None, min_pct: float = 0.0) -> list[dict]:
    rows = [r for r in HOSTS if r["percent"] >= min_pct]
    if region is not None:
        rows = [r for r in rows if r["region"] == region]
    return rows
```

A route handler is thin on purpose: it validates, delegates to a pure function, and returns. The filtering logic is the part worth testing, and it is the same logic the next exercise asks you to write.

### Watch out: The Trap

- Returning `HTTPException` from a helper instead of raising it. Only a raised exception becomes a status code; a returned one becomes a `200` body.
- Validating in the handler after the insert. The database now holds the bad row and the client got a `201`.
- Marking every query parameter required. Optional filters need defaults, and the default must be the unfiltered value.

## Waypoint 3: Status Codes that Tell the Truth

Returning a `"not found"` body with `200 OK` breaks every probe that checks `response.status_code`. Speak the protocol:
- `200 OK` for a successful read
- `201 Created` when a `POST` stores a new resource
- `422 Unprocessable Entity` when validation fails
- `401 Unauthorized` when credentials are missing
- `404 Not Found` when the host does not exist

`raise HTTPException(status_code=404, detail="Host not found")` aborts the handler and sends that exact status with a JSON body. `@app.post("/readings", status_code=201)` sets the success code declaratively.

```python
from fastapi import FastAPI, HTTPException
from pydantic import BaseModel, Field

app = FastAPI()
STORE = {}

class ReadingIn(BaseModel):
    hostname: str
    percent: float = Field(ge=0)

@app.post("/readings", status_code=201)
async def create_reading(payload: ReadingIn) -> dict:
    host = payload.hostname.strip().lower()
    if not host:
        raise HTTPException(status_code=422, detail="hostname required")
    STORE[host] = {"hostname": host, "percent": float(payload.percent)}
    return STORE[host]
```

The `if` is a business rule, not a type rule: Pydantic accepts an empty string as a valid `str`. Validation at the boundary catches the wrong type; the handler catches the wrong value.

### Watch out: The Trap

- Using `404` for a malformed payload. The route exists; the body is wrong. That is `422`.
- Letting a `KeyError` become a `500`. An unhandled exception is a bug in your service, not a client error, and FastAPI will report it as such.
- Returning the created object with `200`. `201` tells the client a resource now exists; caches and retries depend on that distinction.

## Waypoint 4: Testing Endpoints Without Opening a Port

`TestClient` replaces the network with an in-memory call: it takes the `app`, runs the ASGI application, and returns a response object with `.status_code` and `.json()`. Tests stay fast, deterministic, and port-free.

The database is the other dependency. `Depends(get_db)` asks FastAPI for a connection; tests override that dependency with an in-memory SQLite database, so the real `ops.db` is never touched.

```python
import sqlite3
from fastapi import Depends, FastAPI, HTTPException

app = FastAPI()

def get_db():
    conn = sqlite3.connect(":memory:")
    conn.row_factory = sqlite3.Row
    conn.execute("CREATE TABLE readings (hostname TEXT PRIMARY KEY, percent REAL NOT NULL)")
    try:
        yield conn
    finally:
        conn.close()

@app.post("/readings", status_code=201)
def create_reading(payload: dict, conn: sqlite3.Connection = Depends(get_db)) -> dict:
    host = payload["hostname"].strip().lower()
    percent = float(payload["percent"])
    with conn:
        conn.execute(
            "INSERT OR REPLACE INTO readings (hostname, percent) VALUES (?, ?)",
            (host, percent),
        )
    return {"hostname": host, "percent": percent}

@app.get("/readings/{hostname}")
def get_reading(hostname: str, conn: sqlite3.Connection = Depends(get_db)) -> dict:
    row = conn.execute(
        "SELECT hostname, percent FROM readings WHERE hostname = ?",
        (hostname.strip().lower(),),
    ).fetchone()
    if row is None:
        raise HTTPException(status_code=404, detail="Not found")
    return {"hostname": row["hostname"], "percent": row["percent"]}
```

The test owns the connection and never opens `ops.db`:

```python nonRunnable=true reason="TestClient starts a worker thread; the browser sandbox is single-threaded. Run this locally with pytest."
from fastapi.testclient import TestClient

client = TestClient(app)

def test_create_and_missing():
    created = client.post("/readings", json={"hostname": "srv-01", "percent": 92.5})
    assert created.status_code == 201
    assert client.get("/readings/srv-99").status_code == 404
```

### Watch out: The Trap

- Hardcoding `sqlite3.connect("ops.db")` inside the handler. Every test run pollutes your real local database.
- Returning the traceback in `detail`. Log it server-side; send a safe message to the caller.
- Testing only the happy path. `404` and `422` are where the unhandled exceptions live.
