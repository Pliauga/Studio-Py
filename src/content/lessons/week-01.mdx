## The Hook

It is 2:47 AM and the primary storage node on `srv-07` is filling up fast. Someone left a sticky note on the monitor with the disk capacity and current usage, and you are doing percentage math on a phone calculator while the alert channel pings. You do not need a dashboard yet. You need Python to hold two numbers, divide them without lying about the types, and print one clean status line you can paste into the ticket.

## Waypoint 1: Print What You Mean, Name What You Keep

`print()` writes whatever you hand it to the terminal, one line per call. Pass multiple items separated by commas and Python prints them with a single space in between.

A **variable** gives a value a name so you do not have to type the literal twice. The `=` sign assigns the value on the right to the name on the left. Python reads top to bottom: if you use a name before you assign it, or mistype a single character, execution stops immediately with `NameError`. Reassigning the same name overwrites the old value; anything computed before the reassignment keeps the value it had at the time.

Variable names use `snake_case`: lowercase letters, digits, and underscores, never starting with a digit and never containing spaces or hyphens (`srv_07` is a valid variable name; `srv-07` tries to subtract `7` from `srv`).

```python
hostname = "srv-07"
used_gb = 190
total_gb = 200

print("Host:", hostname)
print("Used:", used_gb, "GB")

used_gb = 195
print("Updated used:", used_gb, "GB")
```

## Waypoint 2: Every Value Has a Type

Python distinguishes between text and numbers even when they look identical on screen. `"200"` in quotes is a **string** (`str`), `200` without quotes is an **integer** (`int`), and `200.0` with a decimal point is a **floating-point number** (`float`). Calling `type(x)` tells you which one you are holding.

The type decides what operators do. Between numbers, `+` adds and `*` multiplies. Between strings, `+` glues text together (concatenation) and `*` repeats it. Mixing a string and a number with `+` raises `TypeError`, because Python refuses to guess whether `"200" + 5` should be `205` or `"2005"`.

When data arrives from user input or a text export, it arrives as `str`. Convert it explicitly with `int()`, `float()`, or `str()` before doing math.

```python
raw_used = "190"
total_gb = 200

print(type(raw_used))
print(type(total_gb))

used_gb = float(raw_used)
print(type(used_gb))
print(used_gb + 5)
```

### Watch out: The Trap

- `"190" + "10"` evaluates to `"19010"`, not `200`. No error is raised when both sides are strings.
- `"190" + 10` raises `TypeError`. Convert the string with `int()` or `float()` first.
- `int("87.5")` raises `ValueError`. Parse decimal strings with `float("87.5")` first, then convert to `int()` if you want truncation.
- Quotes around a variable name (`print("hostname")`) print the literal word `hostname` instead of the value stored in it.

## Waypoint 3: Arithmetic That Does Not Surprise You

Standard arithmetic uses `+`, `-`, `*`, and `/`. In Python, `/` always produces a `float`, even when two integers divide evenly: `200 / 100` is `2.0`.

Three additional operators show up constantly in infrastructure scripts: `//` performs floor division (the whole-number quotient, dropping the remainder), `%` returns the remainder (modulo), and `**` raises a number to a power.

Parentheses control evaluation order. Calculating a percentage or a delta without parentheses around the subtraction (`used - baseline / total`) divides `baseline` by `total` first and hands you nonsense without warning.

```python
used = 87
limit = 100

percent = (used / limit) * 100
remaining = limit - used
print(percent)
print(remaining)

total_minutes = 135
hours = total_minutes // 60
minutes = total_minutes % 60
print(hours, "hours", minutes, "minutes")
```

## Waypoint 4: One Clean Line with f-strings

Gluing strings and numbers together with commas or `str()` calls gets noisy the moment a line has three values and a unit sign. An **f-string** prefixes the opening quote with `f` and evaluates any expression inside `{}` directly into the text.

Add a format specifier after a colon inside the braces—such as `:.1f` for one decimal place or `:.2f` for two—to stop floating-point inaccuracy (`87.33333333333333%`) from cluttering an alert line.

```python
hostname = "srv-07"
used = 187.5
limit = 200.0
percent = (used / limit) * 100

print(f"{hostname}: {used} GB of {limit} GB ({percent:.1f}%)")
```

### Watch out: The Trap

- Omitting the leading `f` before the quote prints the literal characters `{hostname}` instead of the variable's value.
- Using `^` for exponentiation (`2 ^ 3`) performs bitwise XOR (`1`), not powers. Use `**`.
- Dividing by zero (`used / 0`) immediately halts the script with `ZeroDivisionError`.
